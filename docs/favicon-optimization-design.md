# 书签图标获取与缓存优化方案

状态：用户已确认，集成实现、独立审查修复和全量自动化测试已完成。真实页面验收受浏览器工具状态限制，目标 LuCI 当前要求登录。日期：2026-11-12。

## 1. 结论与范围

采用端侧持久缓存优先、公网按需获取、内网端侧直连的组合。普通页面刷新不重新发现已有图标，网络故障不移除已成功图片。获取顺序、缓存和失败处理集中实现，首页与管理员画布共用。

保留默认关闭图标、图片位于文字左侧、16px 方形及 4px 圆角、失败字母牌。移动端沿用现有尺寸。保留 CSS 裁剪，不要求浏览器读取外站图片像素。

本次包含自动图标、可选第三方回退、独立端侧缓存、服务端共享缓存、单项刷新、自定义图标 URL、请求资源限制及安全校验。第三方回退默认关闭，由部署者明确开启。服务端禁止抓取私网、回环及链路本地地址，不提供内网代抓白名单。图片缓存独立于导航配置和口令同步。自定义图标 URL 随书签配置同步。服务端公网图标按规范化 origin 全局共享，不按匿名用户、设备或同步空间复制存储。

本次不增加浏览器扩展、运行无头浏览器绕过防护、图片上传平台、付费图标服务、定时全站爬取或任意来源插件系统。

## 2. 当前问题与证据边界

| 问题 | 已知证据 | 设计处理 |
|---|---|---|
| Gemini 无图标 | Node 页面抓取报 UND_ERR_HEADERS_OVERFLOW；真实图标位于 gstatic，三个常用路径均 404 | 专用抓取客户端合理扩大响应头上限，解析页面声明，第三方兜底 |
| linux.do 无图标 | 页面和候选地址返回 403；防护页含 data:image SVG 图标 | 有限读取 403 HTML 中的图标声明，支持内嵌图片，第三方兜底 |
| 内网 LuCI | 未在目标局域网验证 | 浏览器优先直连，可指定实际图标路径；明确 HTTP/HTTPS 和权限限制 |
| 缓存结果不稳定 | 原实现内存缓存；错误页曾按扩展名识别为图片；现有补丁已初步落盘和校验 | 可验证的本地成功缓存与失败退避，保留旧图 |
| 大量书签可能触发限流 | 图标与公开接口共用每 IP 每分钟 120 次额度；生产环境尚未确认 429 | 独立额度与全局并发控制 |
| 图片请求键不统一 | 前端传完整书签 URL，服务端按 origin 缓存 | 自动图标统一 origin，避免重复与敏感路径传输 |
| 静态缓存升级误删 | sw.js 激活时删除所有非当前版本缓存 | 静态资源清理只匹配静态缓存命名空间 |

上述证据来自本次项目检查和上一轮抓取，不代表目标部署环境已经完成验收。行业来源见 favicon-research.md。

## 3. 请求流程

### 3.1 公网自动图标

1. 图标开关开启且书签进入可视区域后，计算规范化 origin。
2. 先读页面内存，再读浏览器持久缓存。有图片立即展示。
3. 端侧以 nextCheckAt 判断是否需要检查；成功确认后默认 30 天内不发自动请求。到期记录仍立即展示，只在页面可见且在线时后台检查。具体时间更新规则见第 4.4 节。
4. 无缓存且未到失败重试时间，显示字母牌，不发请求。
5. 需要获取时，由端侧队列请求同源 `/api/icon?url=<origin>`。端侧不直接访问第三方聚合服务。
6. 服务端先返回新鲜磁盘或内存缓存；缓存过期则立即返回旧图并合并后台更新；完全缺失才执行发现。
7. 新图片在浏览器解码成功后原子替换旧缓存。解码失败保留旧图并进入退避。

页面刷新、切换主题、编辑重绘、同站点多个书签不得各自重复发现。关闭图标时停止新的队列任务，取消无其他使用者的在途端侧请求；已有缓存继续保留。

### 3.2 服务端公网发现顺序

1. 抓取 origin 首页，读取 HTML 头部最多 256 KiB，大小写无关地识别 head 结束标签，正确处理跨分片字符。
2. 解析精确 rel token 的 icon、shortcut icon、apple-touch-icon；支持合法 base href、重定向后的相对路径及必要 HTML 实体解码。
3. 如果页面有 manifest，读取最多一个、64 KiB 的 JSON，提取 icons；manifest 和图片地址均重新执行网络安全校验。
4. 对候选稳定排序：明确的站点图标优先，SVG 与适合 32 至 128px 的位图优先；不把任意 Open Graph 封面当作图标。最多验证六个候选。
5. 补充 `/favicon.ico`、`/favicon.png`、`/apple-touch-icon.png`，统一去重并受候选数量及总预算限制。
6. 无可用图片且部署者显式配置 `PABU_ICON_FALLBACK_PROVIDERS=google,duckduckgo` 时，才依次尝试列出的第三方服务。默认不配置任何服务。只发送规范化公网 origin，不发送路径、查询、用户标识或完整书签；日志记录来源但不记录传送的完整请求。README 与 `.env.example` 明示开启后域名会交给所选服务处理。
7. 每个发现任务从入队起共用 20 秒预算，包含排队、DNS、连接、重定向及读取；单个网络请求最多 5 秒且不能超过剩余预算。最后 5 秒留给第三方兜底，届时取消未完成的页面候选。排队最多 3 秒，超时返回 503，不记站点失败。任务到期取消剩余网络操作。

页面返回 403 时仅从受限 HTML 中提取图标声明，不执行脚本、不提交挑战、不发送用户 Cookie。认证错误不自动提交凭据。data:image 只接受允许的图片类型和有界解码内容，沿用图片校验。

专用客户端响应头上限初始设为 64 KiB，仅用于图标抓取。实施时先核实当前 Node 和已安装依赖能否按请求配置；若需要新增直接依赖，应单独提出，不能通过修改 Node 全局响应头限制影响其他请求。客户端实例复用连接。

第三方返回默认通用图标时不得当作真实图标成功：优先使用上游“缺失时返回失败”的能力，无法可靠区分的默认图片按不确定结果处理，不覆盖已成功的站点原图。实施前需验证两个上游当前行为。

### 3.3 内网自动图标

识别字面私有 IPv4/IPv6、回环地址、localhost、单标签名称及约定的 .local 内部名称。域名是否解析到内网由服务端额外校验，端侧启发式分类不能代替服务端校验。

端侧依次用 Image 加载同 origin 的 `/favicon.ico`、`/favicon.png`、`/apple-touch-icon.png`，最多三个，加载成功才展示。对于 LuCI 可在编辑书签时指定真实图标路径。

端侧直连每个候选最多 3 秒、从入队起整个序列最多 8 秒，计入端侧最多 4 个并发槽位；排队最多 5 秒，每个候选还受剩余总预算约束。自定义图片只有一个候选，沿用 3 秒加载期限。成功地址再次使用时也受期限约束。超时、切换地址或组件销毁时清除计时器和事件处理，尽可能停止图片加载并释放队列槽位；使用请求代次忽略迟到的 load/error，避免覆盖新图。浏览器未必能立即中止底层图片连接，不把释放逻辑槽位描述为网络连接已关闭。超时进入失败退避，用户取消不记失败。

跨域图片可展示时直接使用 URL；源站不允许 CORS 时不能可靠读出 Blob，因此只保存成功地址和检查时间，持久图片缓存依赖浏览器 HTTP 缓存，不承诺离线可用。不使用 opaque 响应作为成功依据。

HTTPS 导航访问 HTTP 内网 IP，可能被混合内容或本地网络访问权限阻止。遇到限制保持字母牌，编辑面板说明“浏览器无法加载此内网图片，请使用 HTTPS 图标地址”。不发无效的无限重试，不建议关闭浏览器安全保护。

服务端不代取内网图片。公开匿名 API 不提供私网 origin 白名单，以免调用者读取部署环境可访问的内网服务。确需内网图标时仅由用户浏览器直连或填写自定义图标 URL。

## 4. 端侧缓存与状态

### 4.1 存储选择

使用独立 Cache Storage `pabu-bookmark-icons-v1`，仅缓存图标图片及非敏感图标元数据。由页面图标模块管理，Service Worker 仅调整清理规则，不增加全接口缓存。

同源图标响应可读、可校验、可复制为 Blob，便于可靠持久化。失败元数据以合成同源键保存小型 JSON 响应。内网或自定义跨域图片只保存地址及状态，不保存未经验证的 opaque 图片。

读取缓存失败、浏览器存储被清理、配额不足或非安全上下文中 Cache Storage 不可用时，降级到当前页面内存和 HTTP 缓存。缓存故障不得影响导航读取、修改或口令同步。配额不足先清理图标缓存再重试一次。

### 4.2 键、字段与一致性

自动图标键是规范化 origin，保留协议和非默认端口，移除用户名、密码、路径、查询、fragment。相同 origin 共用一张自动图标。不同路径的独立应用通过自定义图标 URL 区分。

自定义图片键基于完整规范化图片 URL，拒绝 URL 内凭据及 fragment；查询参数可能是图片签名，保留但不写诊断日志，也不转交第三方。内网地址受网络环境影响，成功地址只作为候选提示，每次页面生命周期仍需确认加载成功。

成功记录包含图片响应、origin/来源类型、validatedAt、nextCheckAt、lastUsedAt；重试记录包含 nextRetryAt 和失败次数。字段保持最小集合，图片与元数据同一条成功响应保存；失败记录单独保存且不能盖掉旧成功响应。

页面内按键合并 Promise。多标签页优先通过 Web Locks 合并刷新，不支持时允许少量重复，由服务端单飞行收敛。写入前比较请求代次，旧请求不得覆盖用户刚设置的图标。Blob URL 在组件移除和缓存替换后释放。

### 4.3 生命周期与重试

| 情况 | 行为 |
|---|---|
| 新鲜成功缓存 | 当前时间早于 nextCheckAt 时直接展示，无自动请求 |
| 过期成功缓存 | 继续展示，后台更新；失败不删除 |
| 首次失败 | 5 分钟后允许再次尝试 |
| 连续失败 | 30 分钟、2 小时、24 小时退避，最大 24 小时，加入小幅随机抖动 |
| 离线或客户端取消 | 不增加站点失败次数，恢复后由可视区域加载流程重试 |
| HTTP 429 / 503 | 遵守 Retry-After，同时保留旧图 |
| 手动刷新 | 绕过端侧新鲜期限，保留旧图；遵守服务端冷却和安全限制 |
| 自定义图片 URL 变化 | 使用新键加载，旧请求不得回写当前书签 |

只在可视区域、在线且页面可见时处理自动更新；不为失败记录设置永久后台计时器。最多 500 个成功条目、总计 32 MiB，单图接收上限 2 MiB。按最近使用顺序清理，失败元数据最多 500 条并在 7 天无访问后清理。容量是初始设计值，按实测调整，不增加用户配置项。

### 4.4 时间字段与 HTTP 缓存契约

服务端使用 validatedAt 表示最近一次成功获取或确认上游图片未变化的时间，用它判断 7 天新鲜期；ETag 只表示图片字节版本。验证成功但图片未变化时，ETag 保持，validatedAt 前进。失败不得推进 validatedAt。不再混用下载时间和验证时间。

端侧 nextCheckAt 表示本设备下次向 Pabu 检查的时间，与服务端 validatedAt 分开。端侧缓存只有在收到服务端新鲜结果且图片可解码时，才将 nextCheckAt 设为本次接收时间加 30 天。因此，新用户拿到服务端已验证 6 天的图标，仍享有本设备 30 天免检查期；这是明确接受的图标更新延迟。validatedAt 只记录服务端证据时间，不决定客户端检查期限。

| 收到的结果 | 图片处理 | 端侧时间更新 |
|---|---|---|
| 新鲜 200 | 解码后替换或复用相同字节 | 更新 validatedAt，nextCheckAt = 接收时间 + 30 天，清除失败状态 |
| 新鲜 304 | 保留已有图片；无本地图片时去掉条件头重试一次 | 从响应头更新 validatedAt，nextCheckAt = 接收时间 + 30 天 |
| 过期旧图 200 | 可以补入缺失图片，已有图片继续显示 | 保留响应中的旧 validatedAt，不延长 30 天；nextCheckAt 设为接收时间 + 5 分钟 |
| 404 / 502 / 504 / 网络失败 | 保留本地旧图 | 按退避更新 nextRetryAt，不推进 validatedAt；达到 nextCheckAt 和 nextRetryAt 两个时间后才再请求 |
| 429 / 503 | 保留旧图，不计内容失败 | 按 Retry-After 延后检查，缺失时默认 1 分钟 |
| 手动刷新成功 | 替换为此次任务结果，相同图片也算验证成功 | 更新 validatedAt 和 nextCheckAt，清除失败状态 |

Cache Storage 不自动执行上述期限，页面模块负责判断。所有真正需要向 Pabu 检查的自动请求使用 fetch cache: no-store，并显式携带已有图片的 If-None-Match；手动刷新同样绕过 HTTP 缓存，但不携带条件头。端侧直接处理 304 状态，不依赖浏览器将它合并为 200。这样不会被浏览器 HTTP 缓存中的旧 200 阻挡。Cache Storage 不可用时，才降级由 img 和普通 HTTP 缓存提供基本展示。

过期服务端缓存始终返回带旧图标记的 200，不能因为 ETag 相同返回普通新鲜 304；只有服务端记录新鲜时才允许 304。新鲜 200/304 均带 X-Pabu-Icon-Validated-At；旧图 200 同时带 X-Pabu-Icon-Stale: 1。图片未变化的验证也必须刷新磁盘和内存元数据。

旧图响应后不在后台持续轮询：5 分钟到期且书签仍可见、在线、页面可见时允许检查一次；离开或重新打开页面也使用同一 nextCheckAt。连续旧图响应采用 5 分钟、30 分钟、2 小时、24 小时的检查退避，收到新鲜结果后复位。

## 5. 服务端缓存与接口

保留 `/api/icon?url=` 图片接口，自动请求只提交 origin。旧客户端完整 URL 仍接受并立即规范化，只抓 origin 首页，不回显原始敏感路径。

### 5.1 数据归属与共享键

匿名用户各自维护书签；浏览器各自维护本机图片缓存；服务端只维护去重后的公网 origin 图标池。图标接口无需知道用户、设备或同步空间标识，不读取导航文档，不扫描所有用户书签建立索引。只有端侧缓存缺失或到期时按需查询。

例如 1000 个用户各有 200 条书签，共计 20 万条；如果去重后有 5000 个 origin，服务端的逻辑工作集就是这 5000 个站点，实际保留数量还受容量上限约束。该数字仅说明去重关系，不是实际流量预测。

| 数据 | 归属与共享范围 | 服务端缓存键 |
|---|---|---|
| 公网自动图标 | 同一 Pabu 实例的所有请求共享 | 规范化 origin |
| 用户书签、标题和分类 | 原有本地导航与同步空间 | 不进入图标缓存 |
| 自定义图片地址 | 随书签配置同步，由端侧加载 | 不进入公共抓取池，尤其不代理带签名参数的 URL |
| 用户内网图片 | 各自浏览器加载和缓存 | 不进入公共抓取池 |
| 内网图片 | 浏览器端按当前用户网络环境直接加载 | 不进入服务端共享池 |

自动键通过 URL 解析后取 origin：主机名规范化，默认端口归一，保留协议与非默认端口，去掉路径、查询与 fragment。`https://linux.do/latest` 和 `https://linux.do/t/123` 共用 `https://linux.do`；`http://example.com:8080` 独立于 `https://example.com`。不要简单截断字符串或合并所有子域名。用户提交含凭据的 URL 直接拒绝。

公网缓存只收录无用户凭据、无身份相关响应的自动站点图标；同源不同路径需要不同图标时使用自定义地址，不扩大公共抓取键为任意完整书签 URL。

### 5.2 共享索引与命中流程

复用 IconService 的两个 Map：`cache` 保存热点成功图标及有界失败状态，`inFlight` 保存正在读取磁盘或抓取的任务。两者均按 origin 索引，不按用户建 Map。

1. 校验并规范化请求，查询内存 Map，平均查询复杂度 O(1)。
2. 内存存在新鲜图片，更新访问顺序并直接返回。
3. 普通请求命中过期图片时立即返回旧图；满足 nextRetryAt 时才合并后台更新。手动刷新走第 5.4 节的等待结果规则。
4. 内存缺失，检查同 origin 的 inFlight。已有任务直接复用，连磁盘读取也合并。
5. 无任务时，注册一次磁盘读取任务。磁盘有图则提升到内存，按新鲜度返回或安排后台更新。
6. 磁盘也缺失，先检查负缓存与抓取额度，符合条件才进入有界外网队列。
7. 获取成功后替换共享图片，异步原子写盘，所有等待者复用该结果；失败写入共享退避状态，有旧图则保留。
8. 任务完成或失败都移除 inFlight。单个客户端断开时移除该等待者；共享任务继续为其他等待者或已返回旧图的后台更新服务，仍受总预算限制。没有任何使用者的排队冷启动任务可取消，取消不计站点失败。

同一 origin 的冷启动、过期更新和手动刷新使用同一个任务入口。100 个客户端同时首次请求同站点，至多建立一个站点发现任务；其内部候选请求仍受第 3.2 节约束。单飞行只合并任务，不承诺跨进程合并。

### 5.3 淘汰、退避与容量算法

采用 Map + LRU + Singleflight + 过期先返回旧图 + 负缓存退避。当前单实例不引入 Redis、分布式锁、LFU 或预抓取任务。

| 机制 | 实现与复杂度 | 约束 |
|---|---|---|
| 热点查询 | Map 按 origin 查询，平均 O(1) | 键只表示站点，不携带用户身份 |
| 内存 LRU | 命中时删除并重新插入，淘汰 Map 首项，平均 O(1) | 同时约束条数与图片总字节，淘汰内存不删除磁盘 |
| 请求合并 | inFlight Map 复用 Promise | 同 origin 只有一个任务，失败必须清理 |
| 成功过期 | validatedAt 判断新鲜度，旧图先返回 | 过期不等于删除，访问才触发更新 |
| 失败退避 | failureCount 和 nextRetryAt，沿用 5 分钟至 24 小时序列 | 全用户共享失败状态，不能因另一用户访问而重置退避 |
| 磁盘淘汰 | 启动建立有界元数据索引，按最近访问时间排序清理，O(N log N) | 后台串行执行，不在每次请求中扫描排序；访问时间合并写盘 |

服务端成功记录至少包含 image、contentType、etag、source、validatedAt、lastAccessAt、nextRetryAt、failureCount。失败更新只修改重试状态，不伪造 validatedAt，也不把成功图片覆盖为空。负缓存单独计数，随机失败域名不能驱逐全部热点成功图片。

初始内存上限为 500 张、32 MiB；磁盘上限沿用 1000 张、64 MiB；单图最多 2 MiB。负缓存最多 2000 条，7 天无访问清理；内存索引及磁盘文件的元数据和临时文件也必须受限。超大单图即使条数少也按字节淘汰。磁盘满或写盘失败时仍可返回已校验图片，记录诊断并降级，不阻塞导航。

5000 个活跃站点超过初始磁盘条数时，冷门图标会被淘汰并可能再次获取。容量属于部署初始值，不是适用所有规模的保证。依据实际命中率、工作集与服务器资源调整部署常量，暂不增加用户设置项。

### 5.4 持久化与接口契约

服务端复用现有 IconService，拆出内部网络校验和缓存读写职责，调用方无需理解候选来源。成功缓存新鲜期限 7 天；超过期限立即返回旧图，后台合并更新。失败退避与端侧分工，服务端不依赖某一客户端状态。

当前同步写入整个 base64 JSON 的补丁替换为 `.icon-cache/` 内每 origin 哈希命名的一条记录，图片与元数据一起原子写入临时文件后重命名。异步写盘；启动懒读，文件损坏只丢该条记录。最多 1000 条、64 MiB，单图 2 MiB，启动及写入后有界清理。目录和文件限制为当前服务用户访问。缓存属于可重建数据，升级不备份、不迁移入业务数据库；管理脚本更新可以清理该目录，浏览器缓存仍能展示。

旧 `.icon-cache.json` 有界读取并校验后按需迁移，超大或损坏文件忽略，不影响服务启动。旧记录只有 fetchedAt 或 timestamp 时，只迁移已校验图片并将验证状态设为过期，不将旧时间直接当作新验证证据。迁移成功才删除旧文件。忽略缓存目录与临时文件，卸载清理范围随部署文档说明。

| 接口 | 约定 |
|---|---|
| GET /api/icon?url=origin | 返回已验证图片；成功响应含 ETag、图片类型和来源类别 |
| GET /api/icon?url=origin&refresh=1 | 手动刷新；加入同 origin 既有任务或创建一次任务，等待最终结果，遵守全局冷却及退避 |
| 未找到 | 404 + 短期 Cache-Control 与 Retry-After |
| URL/地址策略拒绝 | 400，不尝试第三方 |
| 限流或队列满 | 429 / 503，附 Retry-After，不记为图标内容错误 |

普通图片响应使用 `Cache-Control: private, max-age=86400`，供降级 img 展示使用。主流程使用第 4.4 节的 Cache Storage 期限和 no-store 请求，不依赖 HTTP stale-while-revalidate。图片内容哈希作为 ETag，时间字段头、旧图标记和 304 条件严格按第 4.4 节处理。

手动刷新期间页面继续显示已有图片，接口等待任务结束：成功返回新鲜图片 200，即使字节不变也返回成功验证时间；失败返回 502，任务超时返回 504，受限或过载返回 429/503，均附合适的 Retry-After 并使用 Cache-Control: no-store。服务端和客户端保留原图片，不用旧图 200 冒充刷新成功。端侧收到结果后立即更新图片或提示，无须轮询。

refresh 参数不产生另一份缓存，也不能绕过失败退避。若同 origin 已有任务，刷新加入该任务并获得相同最终结果；否则 60 秒冷却或 nextRetryAt 未到时返回 429。没有创建任务的拒绝请求不能延长冷却。端侧同源 API 加载与手动刷新总期限为 25 秒，包含本机排队；其中本机排队最多 3 秒，为服务端最多 20 秒留下传输和解码余量。客户端到期取消等待，服务端按自己的任务预算清理。

### 5.5 匿名请求与资源保护

浏览器并发最多 4 个，优先可见书签；服务端外网任务全局最多 8 个、每 origin 一个，等待队列最多 64 个。缓存命中独立限额初值每 IP 每分钟 600 次，触发外网任务每 IP 每分钟 60 个新 origin，全局并发另行约束；刷新每 origin 每分钟最多一次。每个共享任务最多保留 128 个等待 HTTP 请求，整个图标路由最多保留 512 个在途 HTTP 请求；达到上限立即返回 503 和 Retry-After: 1。每个 HTTP 请求从进入路由起最多 20 秒，等待已有任务时不重置任务期限，排队时间计入期限。与登录、同步、分享接口额度完全分开。

仅真正创建外网任务的请求消耗外网抓取额度，命中磁盘、内存、负缓存或加入既有任务都不重复扣外网额度。所有 HTTP 请求仍受轻量接口额度约束。无效 URL 在入队前拒绝，不建立永久缓存记录。限流器本身的 IP 状态也需要定期清理和容量上限。

公开匿名场景必须同时限制每 IP 新 origin 数、全局任务数、全局有界队列及缓存容量。每 IP 限流无法单独阻止分布式随机域名请求，全局预算负责最终资源上限。过载返回 Retry-After，不创建无限等待者，不用失败请求持续刷新磁盘状态。同源刷新冷却全用户共享，refresh=1 无法绕过负缓存退避与全局额度。

反向代理部署沿用可信代理与真实 IP 解析规则，不能相信任意客户端 X-Forwarded-For。公网池不按登录态产生不同图片，也不提供通过枚举接口查看全部缓存 origin 的能力。

### 5.6 运行指标与扩展条件

按聚合计数记录端点请求量、内存/磁盘/负缓存命中量、实际站点发现任务数、合并请求数、各来源成功数、失败类别、队列长度、淘汰数及缓存字节量。查询命中率与实际外网抓取次数分开统计，避免把负缓存命中算成图片成功。

初期只使用结构化日志或已有日志能力，不新建监控平台，不记录匿名用户书签清单。用这些结果决定容量与并发调整。只有部署明确改为多进程或多实例、并且重复获取成为实测问题时，再设计共享存储与跨实例任务合并；当前文件缓存按单服务进程管理，不让多个进程无协调写同一目录。

## 6. 图片校验与网络边界

必须在读取过程中限制响应体字节，不能完整 arrayBuffer 后才判断大小。校验 PNG、ICO、JPEG、GIF、WebP 和 SVG 内容；对结构明显损坏的图片拒绝，最终由浏览器解码确认。未实现识别的格式不声明支持，Accept 与校验能力一致。

SVG 只作为 img 或 Blob 图片展示，禁止插入 DOM，返回 nosniff 及适当沙箱 CSP，不执行外部资源；不声称魔数识别等于 SVG 安全清洗。内嵌 SVG 同样遵循此边界。

服务端每次初始请求、候选、manifest 和重定向都校验协议、目标端口和地址。拒绝凭据 URL、云元数据、私网、回环、链路本地、多播及保留地址，不提供例外配置。DNS 解析结果与实际连接地址必须一致，防止重绑定；IPv4 映射 IPv6、IP 的等价写法统一处理。重定向最多 3 次，逐跳校验。不能只检查请求前的 hostname。

图标请求不携带用户站点 Cookie、Authorization、同步令牌或管理员凭据。普通端侧跨域 img 使用 no-referrer；它仍可能按浏览器策略携带目标站 Cookie，此行为无法承诺彻底隔离，不把登录凭据作为获取条件。

服务端完全拒绝私网、回环和链路本地目标，公开匿名调用者无法借图标接口访问部署所在网络。内网书签只由用户浏览器直连，不由服务端代理。日志只记安全规范化 origin、来源、状态分类、耗时和缓存命中，不记录完整书签路径、查询参数或图片正文。

## 7. 用户交互与配置兼容

图标默认关闭。编辑书签新增一个可选“图标地址”，留空自动获取；相邻提供“刷新图标”。失败只在编辑区展示简短状态，不在首页弹错误提示。按钮支持键盘、明确 accessible name 和刷新中状态。

手动刷新保留当前图片，成功后替换，失败提示“暂时无法更新，已保留原图”。清除图标地址后恢复自动来源。没有成功图片时继续用首字兜底，图标占位尺寸固定，不移动标题。

书签 schema 新增可选 iconUrl，缺失与空值按自动模式处理；校验只接受 http/https URL，长度受现有配置体积限制和单字段 2048 字符限制，禁止内嵌凭据。导入导出、同步合并、管理员站点编辑均需完整保留该字段；缓存状态和图片二进制不进入这些数据。

设置中增加“清除图标缓存”，只清理本设备图标和失败记录，下一次按需加载。无需批量强制重抓公网，避免产生请求风暴。站点导航发布仍只修改站点配置，不清理访客缓存。缓存按来源共享且属于当前浏览器站点数据，不具有账号隔离语义，不保存任何身份凭据。

## 9. 分阶段实施与验收

### 首次部署前置门槛

任何阶段进入公开部署前，必须完成并通过地址及 DNS 连接校验、逐跳重定向校验、私网默认拒绝、响应体流式大小限制、任务总预算、全局并发/队列/等待者上限和独立限流。沿用 /api/icon 路径不代表沿用旧抓取安全行为。前置门槛未通过时仅允许本地开发，不发布阶段性版本。

确定性 HTTP 用例覆盖元数据地址、DNS 重绑定、重定向入私网、超大流、慢连接、排队超时及过载拒绝；校验任务与 HTTP 等待者都能在期限内释放。

### 第一阶段：让已成功图标稳定

完成统一 origin 键、端侧独立缓存、成功解码后写入、失败保留旧图、单飞行、并发队列和 SW 清理规则。沿用现有后端接口路径，并落实前置门槛和第 4.4 节时间及条件响应契约。

验收：20 个同源书签只获取一次；成功缓存后连续普通刷新 10 次，30 天新鲜期内不调用图标接口；断网刷新保持已缓存图片；切主题/编辑重绘不重新获取；关闭开关不产生图标请求；SW 更新不删除图标缓存；配额不足不阻断导航。

### 第二阶段：提高自动获取成功率

完成抓取客户端、页面/manifest/data 图片处理、聚合服务兜底、前置安全规则回归、全用户共享 Map 与 LRU、异步磁盘缓存、独立限流和错误分类。

验收：Gemini 响应头场景可定位并通过；403 内嵌 SVG 场景可得到真实图标；HTML 假图、超大流、重定向入私网、DNS 重绑定、私有 IPv6 均被阻止；过期缓存响应立即返回且只启动一次更新；进程重启可读旧图；缓存损坏不影响启动。100 个不同 origin 的页面加载不消耗其他接口额度，队列满按约定返回。

共享缓存专项验收使用独立匿名客户端发起实际 HTTP 请求，至少覆盖：

- 100 个客户端请求同一 origin 的不同书签路径，规范化后只创建一个发现任务，得到同一图片与 ETag。
- 服务重启后从磁盘读取，未过期站点不重新访问外网；热点内存淘汰后仍可从磁盘恢复。
- 100 个请求同时访问过期图标立即得到旧图，后台只更新一次；获取失败不修改原 validatedAt，后续客户端遵守相同退避。
- 不同协议、非默认端口和不同子域名互不串图；自定义签名图片和用户内网地址不进入公网池。
- 注入足够多图片触发条数及字节上限，核对 LRU 热点保留和字节计数；大量随机失败域名不驱逐全部成功缓存。
- 缓存命中、任务合并不重复扣外网额度；跨 IP 请求同站点仍受共享冷却，分布式新域名请求受全局队列与容量约束。
- 同一任务的一个等待者断开，不影响其他请求；任务异常后 inFlight 可清理并在到期后重试。达到每任务 128 个或路由全局 512 个等待请求时拒绝新增请求，断开、超时后计数归还。
- 控制时钟验证新鲜 200、304、过期旧图和失败时的时间字段；相同 ETag 的成功重新验证能推进 validatedAt，旧图不能延长 30 天。
- 预置一天有效的旧 HTTP 响应后执行自动检查与手动刷新，确认 no-store 请求到达服务端；刷新成功立即显示任务结果，失败只提示且保留原图。
- 用慢上游占满 8 个任务及 64 个排队位置，排队 3 秒、任务及请求 20 秒内释放；新等待者不延长既有任务期限。

容量与效率专项采用固定的 5000 个模拟 origin 和固定请求序列，先执行无淘汰的大容量对照，再执行初始容量。分别记录冷启动与暖缓存阶段的内存/磁盘命中率、成功图片命中率、实际外网发现次数、淘汰数、P95 响应时间和峰值内存。测试既包含固定热点的偏斜分布，也包含均匀访问，明确初始 1000 条磁盘缓存的适用范围。固定热点可容纳时，暖缓存阶段相同热点的外网发现次数应为零；均匀工作集超容量时允许再获取，但必须报告额外抓取量，不能只写 LRU 正确。容量调整依据测试与实际部署资源，不能据模拟流量承诺生产命中率。

### 第三阶段：内网与编辑闭环

完成端侧直连、自定义 iconUrl、刷新和清除入口、schema/同步兼容、部署配置与文档。

验收：同局域网 HTTP 页面可加载 LuCI 的实际图标地址；HTTPS 页面加载 HTTP 私网地址遇阻时有正确兜底；自定义 HTTPS 图片能加载；两个同步设备都保留 iconUrl、独立建立图片缓存；管理员编辑不会更改访客导航。旧配置无须迁移即可使用。内网候选不响应时在单次 3 秒、总计 8 秒预算内释放逻辑槽位；修改自定义地址后迟到的旧 load/error 不覆盖当前图标；销毁组件不泄漏计时器与 Blob URL。

### 最终验证

依项目工作流执行全部 Node 测试、相关 node --check 与 git diff --check。浏览器闭环统一使用 ego-browser，覆盖普通刷新、强制刷新、离线、两标签页、两主题及窄屏。普通刷新与开发工具禁用 HTTP 缓存分开记录，后者仍应优先命中应用图标缓存。

公网样本逐一检查 Gemini、uhdnow.com、iguopin.com、linux.do、habu.emolu.cn；记录来源、是否为真实图标、首次耗时、缓存命中、刷新次数和错误类别。LuCI 另列为目标局域网验收。真实公网结果与确定性测试分别报告，不把某次上游暂时成功当作永久保证，也不虚构整体成功率。

当前项目缺少 bcrypt 与 better-sqlite3 等依赖，完整 HTTP 验收需要可运行的既有依赖环境；本方案不包含安装新依赖的授权。

## 10. 取舍与待实测事项

本方案建议作为完整实施范围，缓存层优先开发，所有公开部署均须先通过安全前置门槛。端侧 Cache Storage 能稳定保存同源成功图片，但浏览器清理站点数据或回收空间后仍需重新获取。内网跨域图片的强持久缓存受 CORS 限制，不作同等承诺。

第三方兜底可提高覆盖面，也会把用户书签涉及的公网域名交给第三方，因此默认关闭，仅由部署者显式启用。服务端直抓仍可能被站点防护或目标网络阻断，自动获取不承诺 100% 成功。自定义图片地址是本轮可靠的人工补充入口，文件上传保留为后续独立需求。

实施前需用当前运行时验证专用客户端能力、两个第三方服务的默认图行为和实际可达性。以上属于技术验证工作，不改变已确定的产品流程。
