# 当前工作

## 目标

完成 Pabu 与 Habu 的独立拆分，提供独立的产品标识、版本、存储命名和部署说明。

## 完成情况

- 保留导航管理、本地配置、管理员默认模板、口令同步、邀请码治理、同步空间治理和临时加密文本分享。
- 移除服务器监控与 Go agent、私人收藏库、备忘与待办、时间线、微博热搜和 WebDAV。服务器端对应接口返回 404。
- 邀请码采用管理员签发的一次性策略，有效期 48 小时，不开放注册。
- Pabu 默认端口为 4001，管理会话 Cookie 为 `pabu_session`，SQLite 库为 `pabu.db`，访客 IndexedDB 为 `pabu-personal`，Service Worker 缓存使用 Pabu 标识。
- 版本从 `0.1.0` 开始。初始提交 `4de2dd8` 已推送到 `https://github.com/mh567/pabu` 的 `main`，并发布 v0.1.0；Release 不附带二进制包，部署通过仓库源码执行 `npm ci`。

## 边界

导航同步内容由服务端保存并可读取，不提供端到端加密；临时文本分享使用浏览器加密。实时传文件依赖 WebRTC 与 HTTPS，默认只配公共 STUN，未配置 `PABU_RTC_TURN_SECRET` 时不启用 TURN，跨对称 NAT 或严格防火墙可能直连失败，需要回退服务器中转。信令服务器能看到会话元数据、SDP 与 ICE 候选，看不到文件内容；4 位确认码用于发现信令被替换，需要双方人工核对。5 位码空间约 9 万种，安全性依赖单接收方、短 TTL、加入限流与发送方确认。少量未引用的旧功能 CSS 规则仍保留，暂未影响界面与接口。

## 2026-11-27 文本分享 6 位数字短码简化与有效期收紧

- 遵循最简原则，移除 26 位高安全长码选项与对应加密分支，统一使用 6 位数字取件码（如 `482 915`），减少用户选择负担。
- 6 位短码在浏览器通过 `crypto.getRandomValues` 均匀生成，使用随机盐和可选 PIN 经 PBKDF2-SHA256 派生 AES-GCM-256 密钥加密正文（密文前缀 `s1:`），同时向服务端只发送域分离派生的 26 位散列 ID 与取件证明，冲突时自动重试最多 3 次。

- 服务端 `/api/p/:code` 与 `GET /p/:code` 共用 15 分钟内最多 10 次失败尝试的按 IP 限流，防止 6 位短码被在线枚举；同一 IP 对同一分享错 3 次 PIN 仅锁定该 IP 15 分钟而不删除记录，累计错误达 20 次才触发分布式熔断销毁。`/p/:code` 取件页支持 6 位短码与可选 PIN 解密。
- 移动端窄屏（≤600px）恢复显示搜索框下方的「分享文本」「分享文件」「取回文本文件」可点击胶囊并隐藏 `<kbd>` 键盘提示，粗指针下触控高度补齐 44px；结果面板支持点击大号取件码直接复制，粘贴短码自动按 `3-3` 分组格式化。
