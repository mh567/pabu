## 对外契约与安全约定

- 现有 `GET /api/icon?url=` 路径保持。新客户端只发送规范化 origin；旧客户端完整书签 URL 仍接受，但服务端仅取 origin，不记录或回显路径、查询和 fragment。
- 成功图片以图片响应返回，带 ETag、`X-Pabu-Icon-Validated-At` 和 stale 标记。端侧专用 Cache Storage 负责 30 天检查期，HTTP 缓存只作 `<img>` 降级。
- 普通请求命中服务端过期图时立即返回旧图并合并后台更新。手动刷新 `refresh=1` 等待共享任务完成，成功直接返回当前验证结果；失败和超时返回明确状态，端侧保留旧图。
- 书签新增可选 `iconUrl` 字段，校验 HTTP/HTTPS、2048 字符上限并拒绝 URL 凭据。该字段随本地配置、导出、口令同步和管理员站点导航保存；图片二进制与缓存状态不参与同步。
- 内网、回环、链路本地、保留地址及解析到这些地址的公网 hostname 均由服务端拒绝，不提供内网白名单或服务端代理。内网图标只从用户浏览器直接加载。
- 第三方图标来源默认关闭。部署者显式设置 `PABU_ICON_FALLBACK_PROVIDERS` 后，仅将公网 origin 交给配置的服务，不传完整 URL。说明同步更新 `.env.example` 和部署文档。
- 获取器只能访问 80/443 端口，DNS 解析和实际连接地址绑定，逐跳校验最多 3 次重定向，响应体边读边限长。Node 内置 `http`/`https` 可完成连接 pinning 时不新增依赖；做不到则停止后端实现并报告方案阻塞，不退回只校验 hostname 的弱实现。
- 所有公网部署先满足 SSRF、防重绑定、响应体、任务预算、并发、等待者和独立限流门槛，随后才启用获取接口。

## 实施阶段

### 阶段 0：确认与基线隔离

1. 用户确认本计划及上述接口约定。
2. 捕获当前图标差异到仓库外补丁，检查 `git status` 与每个差异，再恢复干净 `main` 工作区，不提交。
3. 运行基线相关测试。按仓库规则不安装依赖；缺依赖的失败记录下来，纯 Node 单测优先执行。
4. 固定两个 worktree 的输入基线和以下 API 契约，然后并行开发。每个任务先写失败测试并观察预期失败，再写最小实现。

### 阶段 1A：服务端获取与共享缓存

独立 worktree：`codex/favicon-server`。范围：

- `lib/icon-service.js`、`server.js`、独立图标 HTTP 测试与服务单测。
- origin 规范化、图片发现、第三方显式开关、连接地址 pinning、重定向/响应大小/时间约束。
- 全用户共用 Map 与 `inFlight`，按 origin Singleflight；内存 LRU 同时受条数和字节上限约束。
- 按 origin 哈希落盘，惰性读取、原子异步写入、有界清理；坏缓存不阻止服务启动。
- 7 天验证期限、旧图 stale 响应、等待式手动刷新、ETag 与独立限流/并发/等待者上限。

### 阶段 1B：端侧缓存与书签体验

独立 worktree：`codex/favicon-client`。范围：

- 新建 `public/bookmark-icons.js`，统一首页与管理员画布的端侧图标加载、Cache Storage、失败状态、可见区队列和去重。
- 新增可选书签 `iconUrl`，更新导航 schema、书签编辑表单、导入导出、同步和管理端拷贝路径。
- 首页仍默认隐藏图标；图片在标题左侧，保留统一尺寸和首字兜底；提供单项刷新与本机缓存清除。
- 私网/内网图标只由浏览器直连，超时、旧事件和 HTTP/HTTPS 混合内容有明确降级。
- 调整 `public/index.html`、Service Worker 版本和缓存清理规则；图标缓存须跨 SW 版本保留。

两个任务使用同一接口契约，但代码范围与主要测试文件分离。并行最多两个 worktree。worker 不提交、不推送、不改版本号和发布记录，不安装依赖；完成后返回变更清单、测试结果和 worktree 路径。
